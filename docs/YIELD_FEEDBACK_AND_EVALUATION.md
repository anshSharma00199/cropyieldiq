# Actual Harvest Feedback and Yield Model Evaluation (T7)

This document details the actual harvest reporting and retrospective evaluation system implemented in CropYieldIQ.

---

## 1. Overview & Architectural Boundaries

CropYieldIQ maintains a strict separation between:
1. **Crop Recommendation System**: Recommends crops suited to soil/climate features. Uses `predictions` and `feedback` tables.
2. **Crop Yield Forecasting System**: Predicts harvested crop yield in kg/ha with conformal prediction intervals. Uses `yield_predictions` and `yield_outcomes` tables.

Actual harvest outcomes reported by farmers provide crucial ground truth to monitor real-world model accuracy and interval coverage over time.

---

## 2. Data Model

### `yield_predictions`
Persists each yield prediction generated by `POST /api/v1/yield/predict`:
- `id`: Integer primary key (returned as `prediction_id` in API responses).
- `user_id`: Foreign key to `users.id`, indexed.
- `inputs`: JSON dictionary containing validated inputs (`crop`, `state`, `area_ha`, `year`, `lag_yield`, `temp_mean`, `rainfall`).
- `yield_kg_per_ha`: Point forecast in kg/ha.
- `interval_lo`: Conformal lower prediction interval bound in kg/ha.
- `interval_hi`: Conformal upper prediction interval bound in kg/ha.
- `model_version`: String identifying the model bundle version.
- `created_at`: Naive UTC timestamp, indexed.

### `yield_outcomes`
Records actual measured harvest results submitted by users:
- `id`: Integer primary key.
- `yield_prediction_id`: Foreign key to `yield_predictions.id`, unique and indexed (enforces at most one outcome per prediction).
- `user_id`: Foreign key to `users.id`, indexed.
- `actual_yield_kg_per_ha`: Float strictly positive and $\le 100,000$ kg/ha.
- `harvest_date`: Optional date (`YYYY-MM-DD`).
- `notes`: Optional string (up to 500 characters).
- `created_at`: Naive UTC timestamp.

## 3. How to Submit a Harvest Outcome

### API Endpoint: `POST /api/v1/yield/outcome`
**Access:** Authenticated user (`farmer`, `expert`, or `admin`).

#### Request Schema (`YieldOutcomeIn`):
```json
{
  "yield_prediction_id": 142,
  "actual_yield_kg_per_ha": 2840.5,
  "harvest_date": "2026-10-15",
  "notes": "Good monsoon season, minimal pest damage."
}
```

#### Field Constraints:
- `yield_prediction_id`: Positive integer. Must belong to the authenticated user.
- `actual_yield_kg_per_ha`: Float > 0 and $\le 100,000.0$ kg/ha. NaN, Infinity, zero, and negative values are rejected with HTTP 422.
  - *Rationale for 100,000 kg/ha bound:* World-record grain yields for cereals/legumes peak under 25,000–35,000 kg/ha; high-moisture sugarcane rarely exceeds 100,000 kg/ha. Capping at 100,000 kg/ha guards against gross data-entry errors (e.g. entering total farm yield instead of per-hectare rate) while accommodating all agronomic possibilities.
- `harvest_date`: Optional ISO 8601 date string.
- `notes`: Optional string up to 500 characters.

#### Response: `201 Created`
```json
{
  "status": "recorded",
  "id": 58,
  "yield_prediction_id": 142,
  "actual_yield_kg_per_ha": 2840.5,
  "harvest_date": "2026-10-15",
  "notes": "Good monsoon season, minimal pest damage."
}
```

#### Security and Integrity Rules:
- **Ownership Isolation:** Users can only submit outcomes for their own predictions. Non-existent IDs or IDs belonging to other users return `404 Not Found` (preventing ID enumeration).
- **Uniqueness & Race Handling:** Only one outcome is allowed per prediction. Duplicate submissions return `409 Conflict`. Database concurrency races are caught safely via `IntegrityError` rollback.

### Streamlit UI Workflow
In the Streamlit application under **Tab 5 ("Yield Forecast")**:
1. When a prediction is made, the platform displays the **Prediction ID**.
2. A dedicated **Record Actual Harvest Outcome** form is rendered directly beneath the prediction result.
3. Users are reminded: *"Please submit your actual measured harvest yield only after harvest is complete."*
4. Submitting the form records the outcome and displays the newly assigned outcome ID.

## 4. How to Access Evaluation Metrics

### API Endpoint: `GET /api/v1/admin/yield/evaluation`
**Access:** Restricted to `expert` or `admin` roles (returns `403 Forbidden` for `farmer`, `401 Unauthorized` for unauthenticated).

#### Response When Outcomes Exist:

## 5. Metric Definitions and Units

| Metric | Key(s) | Unit | Formula | Description |
|---|---|---|---|---|
| **Sample Count** | `sample_count`, `count` | integer | $n$ | Total number of recorded harvest outcomes paired with valid yield predictions. |
| **Mean Absolute Error (MAE)** | `mae` | kg/ha | $\frac{1}{n}\sum_{i=1}^n \|\hat{y}_i - y_i\|$ | Average magnitude of forecast error regardless of direction. |
| **Root Mean Squared Error (RMSE)** | `rmse` | kg/ha | $\sqrt{\frac{1}{n}\sum_{i=1}^n (\hat{y}_i - y_i)^2}$ | Penalizes large outlier forecast errors more heavily than MAE. |
| **Mean Error / Bias** | `mean_error`, `bias` | kg/ha | $\frac{1}{n}\sum_{i=1}^n (\hat{y}_i - y_i)$ | Directional bias. Positive = model overpredicts yield; negative = underpredicts. |
| **Mean Absolute Percentage Error (MAPE)** | `mape` | % | $\frac{100\%}{n}\sum_{i=1}^n \frac{\|\hat{y}_i - y_i\|}{y_i}$ | Percentage error relative to actual yield (calculated on non-zero actuals). |
| **Inside Interval Count** | `inside_interval_count`, `inside_intervals` | integer | $\sum_{i=1}^n \mathbb{I}(y_i \in [\text{lo}_i, \text{hi}_i])$ | Count of predictions where actual harvest fell within the stored prediction interval. |
| **Interval Coverage** | `coverage_percentage` (%) / `coverage_ratio` (0-1) | % / ratio | $\frac{\text{Inside Count}}{n} \times 100\%$ | Empirical coverage of the conformal prediction intervals. Compare against nominal $1 - \alpha$ (e.g. 90%). |

## 6. Limitations of Self-Reported Harvest Data

1. **Self-Selection / Reporting Bias:**
   Farmers submit harvest numbers voluntarily. Farmers with bumper crops or catastrophic failures may be disproportionately motivated to report, biasing the sample away from typical conditions.
2. **Measurement & Conversion Variability:**
   Actual yields are often measured in local volumetric units (e.g. bags, quintals, carts) and converted to kg/ha using approximate area estimates. Moisture content at harvest is rarely standardized.
3. **Unrecorded Confounders:**
   Local microclimates, pest and disease pressure, hail events, irrigation availability, and fertilizer management can heavily alter yield but are not captured in the baseline feature vector.
4. **Not a Formal Proof of Generalization:**
   Retrospective metrics on self-reported farmer outcomes provide valuable operational tracking, but they do **not** replace rigorous, temporal, and region-held-out validation on verified experimental datasets.
